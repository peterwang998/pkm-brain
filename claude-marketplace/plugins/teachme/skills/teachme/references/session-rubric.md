# Session Rubric

Use this checklist to evaluate a `teachme` response or session.

## Core Checks

- Focuses on one concept.
- Infers context before asking questions.
- Asks no more than one calibration question by default.
- Frames the concept as an answer to a real problem.
- Uses a concrete worked example before abstraction for novice-on-topic learners.
- Gives the learner a parallel problem to apply the concept.
- Surfaces at least one misconception, boundary, or adjacent concept.
- Uses a Feynman teach-back or retrieval prompt before ending.
- Corrects errors directly and specifically.
- Keeps each response to no more than three new ideas.

## Failure Modes

- Pure Socratic questioning when the user lacks enough schema.
- Long lecture with no retrieval or application.
- Too many calibration questions before teaching.
- Letting related concepts sprawl into a multi-topic session.
- Giving only recognition-style quizzes instead of generative recall.
- Continuing to hint after the user is clearly stuck.
- Producing an artifact when the user wanted a quick explanation.

## Acceptance Criteria

A good session should leave the learner able to:

- State what problem the concept solves.
- Walk through one concrete example.
- Apply the idea to a nearby new case.
- Name at least one boundary or confusion point.
- Explain the idea back in their own words.
